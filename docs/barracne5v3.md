# Barra CNE5 V3 优化思路

本文档梳理 Barra CNE5 策略的优化方向，作为 V3 变体的设计参考。V3 必须完全独立，不修改 V1/V2/V2.1 任何代码。

---

## 一、现有代码中的未实现缺口

### 1. OOS 因子权重校准（高优先级）

V2 和 V2.1 中 `CalibrateFactorWeightsFromTrainingPeriod()` 均为空桩，仅打印 "not yet implemented - using defaults"。这是 OOS 测试框架的核心——用训练期表现动态优化因子权重，而非固定权重。

### 2. IC/IR 因子有效性验证（中优先级）

设计文档中规划了 V2 的因子 IC/IR 分析，但未实现。没有 IC（信息系数）和 IR（信息比率）监控，无法判断哪些因子在当前市场环境下有效。

### 3. 缺失因子数据

EPIBS、EGIBS、EGIBS_s 三个分析师预期因子无 tushare 数据源，权重被重新分配。`local_data/analyst_estimates/synthetic_consensus_estimates.csv` 已有合成数据但未被使用。

## 二、优化方向（按实现难度和收益排序）

### A. 因子动态权重（Factor Timing）

| 方法 | 思路 | 与现有代码的结合点 |
|------|------|-------------------|
| **因子动量** | 用因子过去 N 期收益率的动量信号调整权重，近期表现好的因子加权重，差的减权 | `SignalModel` 中的 `factorWeights` 字典可改为动态计算 |
| **因子 IC 滚动窗口** | 计算每期因子 IC，用滚动窗口 IC 均值/IR 作为因子权重乘数 | 在 `OnData` 中引入 IC 追踪，替代固定权重 |
| **体制切换（Regime Switching）** | 识别牛市/熊市/震荡市，不同体制用不同权重集（如熊市加大小盘/低波，牛市加大动量/成长） | 可用 Hidden Markov Model 或简单规则（波动率阈值）划分体制 |
| **因子拥挤度调整** | 监控因子持仓拥挤度（同方向持仓占比），拥挤度高时减权 | 需要横截面持仓数据，可从北向资金/融资融券近似 |

### B. 风险控制增强

| 方法 | 思路 | 与现有代码的结合点 |
|------|------|-------------------|
| **波动率目标（Vol Targeting）** | 组合波动率高于目标时等比例缩仓，低于目标时加仓 | V2.1 已有 Sharpe-based scaling，可扩展为 vol targeting |
| **条件 VaR / 尾部风险控制** | 用历史模拟或参数法计算 CVaR，超过阈值时降仓 | 替代当前的固定止损线，是更精细的尾部风险管理 |
| **泊松跳跃过程建模极端事件** | 用泊松过程建模尾部跳空事件的到达频率和幅度，动态调整止损/仓位 | 当前止损是固定百分比，泊松模型可让止损在"跳跃高风险期"自动收紧 |
| **回撤路径管理** | 不仅看回撤幅度，还看回撤速率（回撤速度过快时提前减仓） | 当前 `MaximumDrawdownPercentPerSecurity` 只看绝对幅度 |

### C. 组合构建优化

| 方法 | 思路 | 与现有代码的结合点 |
|------|------|-------------------|
| **因子正交化增强** | V2 已做 ResVol⊥Beta、MoneyFlow⊥Liquidity、Margin⊥Leverage，但可扩展为全量 Gram-Schmidt 或 PCA 正交 | `SafeZScores` 后增加正交化步骤 |
| **协方差收缩估计** | 用 Ledoit-Wolf 或因子模型协方差替代样本协方差，减少估计误差 | `Black-Litterman` 中的 `omega` 矩阵可用收缩协方差 |
| **换手率约束** | 在优化中加入换手率惩罚项，减少交易成本 | 当前只有 `maxSingleWeight` 约束，无换手率控制 |
| **分层选股** | 先按行业/风格分层，每层内再按因子得分选股，避免行业/风格集中 | 替代当前的纯 TopN 排名选股 |

### D. 数据与因子增强

| 方法 | 思路 | 与现有代码的结合点 |
|------|------|-------------------|
| **补齐分析师预期因子** | 接入合成数据或替代数据源（东方财富一致预期） | `barra_cne5v2_factor_builder.py` 中 EPIBS/EGIBS 的 placeholder |
| **高频因子** | 用分钟/Tick 级数据构造微观结构因子（VPIN、订单流不平衡） | 新增因子类，扩展 FactorData |
| **另类数据因子** | 卫星图像、新闻情感、供应链关系等非传统因子 | 作为新 factor family 加入 V2 的 15 因子框架 |

## 三、建议的实施路径

```
阶段1（低风险高收益）：
  ├── 实现 OOS 因子权重校准（已有空桩）
  ├── 实现 IC/IR 因子有效性监控
  └── 补齐分析师预期因子数据

阶段2（中等难度）：
  ├── 因子动量/IC滚动权重（替代固定权重）
  ├── 波动率目标仓位管理
  └── 换手率约束 + 协方差收缩

阶段3（较高难度）：
  ├── 体制切换动态权重
  ├── 泊松跳跃尾部风险模型
  └── 分层选股 + 因子正交化增强
```

每个阶段按项目规范要求：**新功能必须完全独立，不修改已有变体**，即新建 `AShareBarraCNE5V3Algorithm.cs` 及其 SignalModel。

## 四、各优化方法详细设计

### 4.1 因子动量（Factor Momentum）

**原理**：因子收益具有持续性，近期表现好的因子倾向于继续表现好。

**实现方案**：
- 在 SignalModel 中维护每个因子的历史收益率序列
- 计算因子过去 20/60/120 日的累计收益作为动量信号
- 动量信号归一化后作为权重乘数：`dynamicWeight = baseWeight * (1 + momentumScore * sensitivity)`
- sensitivity 参数可配置，默认 0.3

**数据需求**：每期因子收益 = 因子多空组合收益，需在 OnData 中追踪

**风险**：因子动量在拐点处会失效，需配合因子 IC 做确认

### 4.2 因子 IC 滚动窗口

**原理**：IC（因子值与下期收益的秩相关系数）直接衡量因子预测能力，IC 高的因子应获更高权重。

**实现方案**：
- 每个调仓日计算各因子与下期收益的 Spearman rank IC
- 维护滚动窗口（默认 60 期）IC 序列
- 因子权重乘数 = `sign(baseWeight) * max(0, rollingIC_mean / rollingIC_std)` 即 IR
- IR < 0 的因子该期权重置零

**数据需求**：需要保存历史因子值和对应下期收益，内存开销可控

**风险**：IC 估计噪声大，窗口过短不稳定，过长滞后；需设最小样本量门槛

### 4.3 体制切换（Regime Switching）

**原理**：不同市场体制下因子表现差异显著，应动态切换权重集。

**实现方案（简单规则版）**：
- 用市场波动率（沪深300过去20日已实现波动率）划分体制：
  - 低波动体制（< 15%）：牛市特征，加大 Momentum/Growth/EarningsYield
  - 中波动体制（15%-25%）：震荡市，均衡权重
  - 高波动体制（> 25%）：熊市特征，加大 Size/BookToPrice/ResidualVolatility
- 三套权重集预定义，体制切换时平滑过渡（EMA 权重混合）

**实现方案（HMM 版，进阶）**：
- 用 2-3 状态 HMM 拟合市场收益+波动率序列
- Viterbi 解码当前最可能体制
- 每套体制的因子权重通过训练期优化获得

**风险**：体制识别滞后，拐点处切换可能反向；HMM 需要足够长的训练数据

### 4.4 因子拥挤度调整

**原理**：当过多资金追逐同一因子时，因子收益下降、回撤风险上升。

**实现方案**：
- 用北向资金持仓变化近似外资因子暴露
- 用融资融券余额变化近似杠杆因子暴露
- 用公募基金持仓披露近似机构因子暴露
- 拥挤度指标 = 持仓集中度的 z-score
- 拥挤度超过阈值时，该因子权重衰减：`adjustedWeight = baseWeight * max(0.2, 1 - crowdingPenalty * zScore)`

**数据需求**：tushare 的 hk_hold、margin_detail、fund_portfolio 数据

**风险**：持仓数据频率低（公募季报），拥挤度信号滞后

### 4.5 波动率目标（Vol Targeting）

**原理**：组合波动率偏离目标时，通过仓位缩放使实际波动率趋近目标。

**实现方案**：
- 计算组合过去 20 日已实现波动率（日收益标准差 * sqrt(252)）
- 目标波动率默认 15%
- 仓位乘数 = `targetVol / realizedVol`，clamp 到 [0.5, 1.5]
- 乘数应用到所有持仓权重上
- 与 V2.1 的 Sharpe-based scaling 可叠加或替代

**风险**：波动率估计基于历史，极端事件时估计偏低；需配合跳跃模型

### 4.6 条件 VaR / 尾部风险控制

**原理**：CVaR（Expected Shortfall）衡量最坏情况下的平均损失，比 VaR 更保守。

**实现方案**：
- 用过去 252 日日收益率做历史模拟
- 计算 95% VaR 和 99% CVaR
- 当 CVaR 超过阈值（如 -5%）时，按比例降仓：`scale = maxCVaR / currentCVaR`
- 降仓后重新计算 CVaR 确认在阈值内

**风险**：历史模拟假设平稳分布，黑天鹅事件无法覆盖；可结合泊松跳跃模型改进

### 4.7 泊松跳跃过程建模极端事件

**原理**：A 股存在涨跌停、政策冲击等跳跃事件，用泊松过程刻画跳跃到达频率，用对数正态分布刻画跳跃幅度。

**模型**：
- 跳跃扩散过程：`dS/S = mu*dt + sigma*dW + J*dN`
  - `N(t)` 服从强度 lambda 的泊松过程（跳跃到达频率）
  - `J` 服从对数正态分布（跳跃幅度）
- 参数估计：
  - `lambda`：用历史日收益超过 3-sigma 的频率估计
  - `J_mean, J_std`：用超过 3-sigma 的收益样本估计跳跃幅度分布
- 风险控制应用：
  - 计算跳跃调整 VaR：`JumpVaR = mu*T - sigma*sqrt(T)*z + lambda*T*E[J]`
  - 当跳跃强度 lambda 上升时（近期极端事件频发），自动收紧止损和降低仓位
  - 跳跃风险溢价：`lambda * E[|J|]` 超过阈值时，组合整体降仓

**实现方案**：
- 在 SignalModel 或独立 RiskModel 中维护跳跃参数估计
- 每个调仓日更新 lambda、J_mean、J_std
- 用跳跃调整风险指标替代固定止损线
- 止损幅度 = `baseStopLoss - jumpRiskPremium * sensitivity`

**数据需求**：仅需日收益率序列，无额外数据源

**风险**：参数估计不稳定，跳跃事件稀少导致 lambda 估计噪声大；需设最小观测窗口

### 4.8 回撤路径管理

**原理**：回撤速率（单位时间回撤幅度）比绝对回撤水平更能反映市场异常。

**实现方案**：
- 追踪组合净值的回撤路径：`drawdownRate = currentDD / daysSincePeak`
- 当回撤速率超过阈值（如日均回撤 > 1%）时，提前减仓
- 减仓比例 = `1 - min(1, drawdownRate / maxRate)`
- 与现有 MaximumDrawdownPercentPortfolio 配合使用

**风险**：正常波动也可能触发，需区分趋势性回撤和噪声

### 4.9 因子正交化增强

**原理**：V2 仅对 3 对因子做了正交化，剩余因子间仍存在共线性。

**实现方案**：
- 对全部 15 个因子做 Gram-Schmidt 正交化，按因子重要性排序（最重要的先正交化）
- 或用 PCA 提取正交主成分，保留解释方差 > 95% 的主成分
- 正交化后重新计算因子权重（需在训练期重新校准）

**风险**：正交化后因子失去经济含义，难以解释；PCA 主成分的稳定性需验证

### 4.10 协方差收缩估计

**原理**：样本协方差矩阵在股票数量多、样本少时估计误差大，收缩估计可降低误差。

**实现方案**：
- 实现 Ledoit-Wolf 收缩估计：`Sigma_shrunk = alpha * Sigma_sample + (1-alpha) * F`
  - `F` 为单因子模型隐含协方差（用市场因子）
  - `alpha` 由 Oracle Approximating Shrinkage 最优公式计算
- 在 Black-Litterman 模型中用 `Sigma_shrunk` 替代 `omega` 的对角近似

**风险**：收缩过度会抹去真实信号，收缩不足则估计误差仍大

### 4.11 换手率约束

**原理**：频繁调仓产生交易成本，侵蚀收益，需在优化中显式约束。

**实现方案**：
- 在权重优化中加入换手率惩罚：`minimize -score'w + lambda_turn * ||w - w_prev||_1`
- `lambda_turn` 为换手率惩罚系数，可配置
- 或设硬约束：`||w - w_prev||_1 <= maxTurnover`
- 与 Black-Litterman 结合：在 BL 后验权重上做换手率约束投影

**风险**：换手率约束过紧导致跟踪因子信号滞后，错过快速变化的市场机会

### 4.12 分层选股

**原理**：纯 TopN 选股可能导致行业/风格集中，分层选股保证分散化。

**实现方案**：
- 按申万一级行业分层
- 每层内按因子综合得分选股，各层选股数量按行业权重分配
- 行业权重 = 市值权重（中性化）或等权
- 最终组合自动满足行业中性约束

**风险**：行业分类过粗可能无法控制风格暴露，过细则每层股票太少

## 五、V3 架构设计原则

1. **完全独立**：新建 `AShareBarraCNE5V3Algorithm.cs` + `AShareBarraCNE5V3SignalModel.cs`，不修改 V1/V2/V2.1
2. **复用 FactorData**：V3 可复用 `AShareBarraCNE5V2FactorData`（15 因子），如需扩展则新建 FactorData 类
3. **模块化**：每个优化方向实现为独立模块，可通过配置开关启用/禁用
4. **LEAN 原生**：所有回测/统计必须使用 LEAN 原生引擎，不自算（参考 [[feedback_lean-native-only]]）
5. **渐进式**：按阶段实施，每阶段完成后独立回测验证，不跳跃
