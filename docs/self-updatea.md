## 结论：选 C(分阶段),但 A 阶段有一个前置检查容易被忽略,不做的话 A 会静默失效

## 关键前置问题:先查历史轨迹里 alpha 的多样性

CQL/IQL 这类离线 RL 算法能学到东西,前提是数据里对"同一类状态"存在**不同动作的真实结果**可供比对。现在的 `state_trace.jsonl` 大概率是"combined 策略跑一遍、alpha 恒为 1"生成的——如果整条轨迹里动作维度几乎没有变化(全是 1,没有缩放过的历史),离线 RL 没有任何反事实数据可学,CQL 的保守惩罚机制会让 policy 收敛到接近"什么都不做"(alpha≈1),Layer C 就变成了一个学不出风控行为的空壳,而且这个失败是**静默的**——FQE 评估出来可能还显示"没有明显变坏",因为它本来就没学出新东西。
A 阶段要先加一步**低成本的动作多样化**:用现有历史状态,重跑少量(不需要 200 次,可能 5-10 组)固定 alpha 扰动(0.3/0.5/0.7/0.9/1.0 等)的回测,把这些多样化轨迹并入训练集,再上 CQL/IQL + FQE。这一步不需要重写 gym_env,只是多跑几次已有的 LEAN 回测,成本很低,但对 A 阶段是否真的有效至关重要。

## B 阶段:比你想的便宜,因为动作只是"自己仓位的缩放"

这里有个容易被低估的点:B 选项听起来像"重写整个市场模拟器"(冲击成本、订单簿),但 Layer C 的动作只是**对自己既有目标仓位的标量缩放**(alpha∈[0,1]),不涉及对市场价格的冲击建模。这意味着一个**轻量级**的响应式环境是可行的:

- 已有的策略回测本身会算出"未缩放"的每期原始 PnL 贡献(每个 rebalance 点的目标持仓 × 标的收益)
- 给定任意 alpha 序列,可以**重新组合**出该序列下的组合净值/回撤/VaR 路径,不需要重新跑 LEAN,只需要重算加权路径

这比"完整重写 gym_env + 冲击成本模型"轻得多。但有一个真实的近似误差要承认:如果底层策略是按当前净值百分比动态定目标仓位(常见于 LEAN 的 portfolio construction),那么 alpha 改变了 t 期净值,会连锁影响 t+1 期的目标仓位计算——这是路径依赖的复利效应,轻量模拟器做的是一阶近似,不是完全精确复现。这个近似误差应该在切到 B 阶段前,用少量真实 LEAN 重跑做验证(抽样对比近似值 vs 真实重跑值),确认误差在可接受范围。

## 给你的具体路径

1. **A 阶段(本周内)**:先查 alpha 方差 → 大概率需要先做多样化重跑 → 再上 d3rlpy(CQL 或 IQL)+ FQE。这一步的目标不是"最终方案",是**验证现有 policy 是否真的有效**,同时暴露训练数据的真实覆盖范围。
2. **B 阶段(后续)**:构建轻量的"仓位缩放重算"环境(不是完整市场模拟器),抽样对比近似 vs 真实 LEAN 重跑误差,误差可接受后用它训练真正探索式的 PPO/约束 RL。

## FinRL 不需要

FinRL 是端到端的通用金融交易 RL 框架(自己定义 state/action/reward、Gym 环境),定位是"从零搭建一个交易 RL 系统",跟你现在的场景不匹配——你已经有 LEAN 原生的五层架构和成熟的因子/组合/执行层,Layer C 只是在**已有系统上加一层风控缩放**。引入 FinRL 相当于引入一整套平行的环境抽象,和现有 manifest/接口契约的"零侵入"设计哲学冲突,维护成本大于收益。

真正需要的开源依赖是 **d3rlpy**(离线 RL 算法 + FQE 评估工具),这一个就够,不需要额外引入 FinRL。
