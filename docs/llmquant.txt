A股多因子策略说明

1. 策略目标
本策略使用 `/home/project/tushare-downloader/tushare_data` 中的 Tushare parquet 字段构建沪深300股票池上的 A 股多因子策略，并通过标准 LEAN 回测流程执行，不再使用独立 Python 模拟回测作为正式结果。

2. 使用的数据集与字段
- `index_daily/ts_code=000300.SH/data.parquet`
  - `trade_date`
  - `close`
  - `pct_chg`
- `index_weight/date=*/data.parquet`
  - `index_code`
  - `con_code`
  - `trade_date`
  - `weight`
- `daily/ts_code=*/data.parquet`
  - `trade_date`
  - `close`
  - `pct_chg`
  - `amount`
- `daily_basic/ts_code=*/data.parquet`
  - `pb`
  - `ps_ttm`
  - `dv_ttm`
  - `turnover_rate_f`
  - `circ_mv`
- `moneyflow/ts_code=*/data.parquet`
  - `net_mf_amount`
  - `buy_lg_amount`
  - `sell_lg_amount`
  - `buy_elg_amount`
  - `sell_elg_amount`

3. 金融原理
策略采用“价值 + 趋势 + 资金流 + 低波动 + 市场状态过滤”的组合。

3.1 价值因子
- 低 `pb`
- 低 `ps_ttm`

3.2 趋势因子
- `momentum_120_20 = close[t-20] / close[t-120] - 1`

3.3 资金流因子
- `flow_ratio = net_mf_amount / amount`
- `big_flow_ratio = (buy_lg_amount + buy_elg_amount - sell_lg_amount - sell_elg_amount) / amount`

3.4 低风险因子
- `volatility_20 = 20日收益波动率`

3.5 短期反转修正
- `return_5 = 5日收益率`
- 在综合得分中对 `-return_5` 给较小正权重

4. 风控逻辑
4.1 股票层过滤
- 收盘价至少 5 元
- 流通市值 `circ_mv` 至少 1,000,000
- `turnover_rate_f` 至少 0.3
- `flow_ratio` 必须大于 0
- 20日波动率不高于 6.0%

4.2 市场状态过滤与仓位路径控制
策略不再使用“满仓/半仓”二元开关，而是按以下信息构建多档 regime score：
- 沪深300相对 20/60/120 日均线的位置
- 沪深300 20/60 日动量
- 沪深300 20 日波动率
- 沪深300 252 日滚动回撤
- 股票池中的正动量广度、正资金流广度、低波动广度

再把 regime score 映射到目标仓位，并叠加三层路径控制：
- 最低防守仓位 `min-regime-exposure`
- 快降慢升的仓位步进，避免单次调仓把风险一下子重新加满
- 组合回撤进入 recovery 模式后，对仓位继续加上恢复上限，直到回撤修复并且市场状态重新转强

当前正式参数：
- `risk-on-exposure = 1.0`
- `risk-off-exposure = 0.8`
- `min-regime-exposure = 0.55`
- `max-exposure-step-up = 0.30`
- `max-exposure-step-down = 0.45`
- `recovery-drawdown-enter = -0.16`
- `recovery-drawdown-exit = -0.05`
- `recovery-exposure-cap = 0.90`

4.3 持仓路径控制
- 组合采用持仓保留缓冲 `retention-buffer = 6`
- 当前持仓如果仍处于 `top-n + retention-buffer` 的排名带内，则优先保留，降低无意义换仓
- 新目标仓位仍按等权分配，但订单执行遵循 A 股整手与现金约束

5. 标准 LEAN 执行流程
第一步先把 parquet 特征导出成 LEAN 自定义数据 CSV：

`source /root/miniconda3/bin/activate quant311 && python Scripts/export_ashare_llm_quant_feature_data.py --config Launcher/config/config-ashare-llm-quant-feature-export.json`

第二步通过标准 LEAN Launcher 回测：

`./Launcher/bin/Debug/QuantConnect.Lean.Launcher --config Launcher/config/config-ashare-llm-quant-lean-backtest.json`

第三步通过标准 LEAN live-paper 执行实盘仿真：

`python3 Scripts/ashare_llm_quant_live_paper.py --config Launcher/config/config-ashare-llm-quant-live-paper.json`

说明：
- 正式回测入口是 `Launcher/bin/Debug/QuantConnect.Lean.Launcher`
- `Scripts/ashare_llm_quant_backtest.py` 只保留为研究脚本，不作为标准结果口径
- live-paper 也走标准 LEAN Launcher，只是外层由 `Scripts/ashare_llm_quant_live_paper.py` 先启动 live bridge，再启动 `QuantConnect.Lean.Launcher`
- A股交易时段内默认优先走 Tushare 实时日线；非交易时段会自动切换到 GBM 模拟实时日线，用同样的调仓频率驱动策略，便于闭市期间验证 live-paper 全流程
- off-hours 模拟行情会写入 `live-price-snapshot-file`、live feature CSV 和 benchmark CSV，LEAN 数据队列按标准 live 模式读取这些文件，不走旁路 mock 回测

6. LEAN算法实现要点
- Python 只负责把 Tushare parquet 导出为 LEAN 可消费的日频特征文件
- C# 算法 `AShareLlmQuantLeanAlgorithm` 负责标准 LEAN 下单、手续费、持仓和统计
- 算法内部保留最近多日自定义因子快照，避免月初调仓时丢失上个交易日信号
- 调仓时显式按 A 股 100 股整手下单，并预留 `1.5%` 现金缓冲覆盖手续费与整手离散误差
- 基准指数行在加载时补全 20/60/120 日均线、20/60 日动量、20 日波动率和 120/252 日滚动回撤
- 月度调仓前先计算市场 regime score，再计算目标仓位，再按仓位步进和 recovery 模式约束最终目标仓位
- 调仓选股阶段加入持仓保留缓冲，降低组合路径抖动和无效换手

8. 是否满足目标
收益和回撤目标满足，且较上一正式版同时实现了更高收益和更低回撤，但 Monte Carlo 稳健性仍然只是小幅改善结构、未出现显著跃升。

原因：
- 收益高于沪深300超过 5 个百分点
- 最大回撤低于沪深300超过 5 个百分点
- 回测已走标准 LEAN 流程，并产出标准 LEAN 统计结果、订单、手续费、持仓轨迹和 Monte Carlo 稳健性统计
- 新版市场状态过滤和仓位路径控制明显压缩了单路径回撤，并减少了 recovery 模式的持续时间
- 但 63 日 Monte Carlo 结果仍显示组合短中期路径风险偏高，后续还需要继续优化因子分布和横截面信号质量过滤
